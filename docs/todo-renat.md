# Что работает и что можно подкрутить

Прогон вживую как «чистый юзер» (macOS, Python 3.13, ветка master).
**Пайплайн подтверждён ЦЕЛИКОМ:** local-бэкенд из коробки → проект (git-backed, deploy key → `config.json`
в репо) → Flutter web (на 3.41.9) → сбор в клиенте → выгрузка («Очередь → Отправить») → пакет с данными и
медиа в админке → визуализация (yolo-боксы). Проверено и локально, и на живом инстансе.

**Легенда:** 🔴 ломает прогон · 🟠 дока/упаковка/дефолт · 🟦 окружение (не баг репы) · ✅ хорошо.

> **Главное, чего не хватает новичку:** чуть более понятный **README-навигатор** — (1) что где и что поднимать, (2) ссылки на
уже существующие спеки/презентацию/API/viz, (3) step-by-step «с нуля до первого пакета». Документация в
репе обширная и местами отличная, но из README не находится. Плюс точные версии (Flutter 3.41.9) и
обязательные пререквизиты (libpq для psycopg2, GitHub-репо+deploy key для проекта) нигде не перечислены.
> 

## ✅ Что хорошо

- Local-бэкенд (sqlite) поднимается **без правок**: `migrate`→`createsuperuser`→`runserver`, админ-логин в `/ui/`. Firebase для админки не нужен.
- Полный мейн-цикл и визуализация работают end-to-end (локально и на живом).
- Документация по сути **обширная**: `specs/01–09`, config-гайд, viz-спека, API-контракт, целая `specs/presentation/` со схемами/скриншотами.
- Часть пунктов уже закрыта в `dev-web` (firebase-креды, вкладка «Медиа» со счётчиком, ошибки init БД, «двойной review», JSON/удаление пакетов).
