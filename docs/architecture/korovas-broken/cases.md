# korovas-broken — каталог учебных кейсов

Намеренно сломанные сценарии для разбора инцидентов. Стенд и видео-касты — отдельно; здесь описание симптомов и точек диагностики.

Формат кейса: **id · слой · симптом · где смотреть · что делать**.

---

## Upload

### U1 — missing blobs на manifest

| | |
| --- | --- |
| **Слой** | Upload |
| **Как выглядит** | PUT manifest → `422` с `missing_blobs`; пакет не доходит до commit |
| **Где смотреть** | Ответ API; `package_session.phase` = `awaiting_blobs`; список `uploaded_blob` vs ссылки `blobs/…` в `payload.json` |
| **Что делать** | Догрузить недостающие PUT blobs; повторить manifest → commit |

### U2 — обрыв сети mid-upload

| | |
| --- | --- |
| **Слой** | Upload |
| **Как выглядит** | Часть фото ушла, `serverDeliveryState` = `failed` или застрял `uploading`; commit недоступен |
| **Где смотреть** | Drift на клиенте; `uploaded_blob` на сервере; вкладка «Сервер» |
| **Что делать** | Retry с «Сервер» — протокол идемпотентен по blob path; не создавать новый `package_id` |

### U3 — 409 already completed

| | |
| --- | --- |
| **Слой** | Upload |
| **Как выглядит** | POST packages → `409`; повторная отправка «успешного» пакета |
| **Где смотреть** | GET пакета; `phase` = `completed` |
| **Что делать** | Клиент должен пометить локально `serverDeliveryState: completed` (как в спеке 06); не считать ошибкой доставки |

### U4 — нет доступа к проекту

| | |
| --- | --- |
| **Слой** | Auth / Upload |
| **Как выглядит** | Проекта нет в каталоге мобилки или API отвечает отказом на `/v1/projects/...` |
| **Где смотреть** | Firebase пользователь ↔ `CollectorUser.mobile_projects`; staff UI «Права доступа» |
| **Что делать** | Выдать проект в `mobile_projects`, перелогиниться / обновить каталог |

## Datapipe

### D1 — webhook не стартовал после commit

| | |
| --- | --- |
| **Слой** | Datapipe |
| **Как выглядит** | Пакет `completed` в админке, но CVAT / инференс не появились |
| **Где смотреть** | `collector/pipeline.json` в Git; логи webhook / stage 0 datapipe; факт commit в `package_session` |
| **Что делать** | Проверить URL webhook и конфиг пайплайна; перезапустить стадию 0 вручную при необходимости |

### D2 — stage 0 не читает blobs из storage

| | |
| --- | --- |
| **Слой** | Datapipe / Storage |
| **Как выглядит** | Job падает на скачивании фото; в БД сессия есть, файлов нет или 403 |
| **Где смотреть** | `Project.storage_uri` + encrypted options; `uploaded_blob.storage_path`; доступ S3/GCS/file |
| **Что делать** | Починить креды / URI (кнопка «Проверить хранилище» в staff UI); убедиться в trailing slash |

### D3 — нет CVAT link / пустая аннотация

| | |
| --- | --- |
| **Слой** | Datapipe |
| **Как выглядит** | Пакет обработан частично; в viz нет GT / ссылки на CVAT |
| **Где смотреть** | `cvat_link`, `cow_keypoint_annotation`; логи создания задач CVAT |
| **Что делать** | Проверить доступ CVAT и шаг «создать задачу» в стадии 0; догнать импорт аннотаций |

## Visualization

### V1 — пустой слой инференса

| | |
| --- | --- |
| **Слой** | Viz |
| **Как выглядит** | Workspace → Визуализация: слой «Инференс» пуст или отсутствует |
| **Где смотреть** | `cow_inference_result` по `package_id` + `manifest_blob_key`; статус prod-стадии datapipe |
| **Что делать** | Дождаться / перезапустить инференс; сверить, что blob key совпадает с путём фото |

### V2 — сломан viz.json / плагин не рисует

| | |
| --- | --- |
| **Слой** | Viz |
| **Как выглядит** | Данные в БД есть, UI не показывает keypoints / слои |
| **Где смотреть** | `collector/viz.json` (Git SHA = `last_synced_sha`); плагины `api/viz_plugins/`; консоль браузера `/ui/` |
| **Что делать** | Синхронизировать Git-конфиг; исправить id плагина / поля viz; hard refresh админки |

## Storage

### S1 — неверный storage_uri / креды

| | |
| --- | --- |
| **Слой** | Storage |
| **Как выглядит** | Upload или datapipe падают на записи/чтении файлов; в project DB строки есть, объектов в bucket нет |
| **Где смотреть** | `Project.storage_uri`, `storage_options_encrypted`; «Проверить хранилище»; логи `project_media` |
| **Что делать** | Выставить корректный `gs://` / `s3://` / `file://` с trailing slash; обновить креды Fernet |

## Как использовать на занятии

1. Открыть кейс → воспроизвести симптом на стенде (когда `korovas-broken` подготовлен).
2. Пройти колонку «где смотреть» по [diagnostics-checklist.ru.md](../diagnostics-checklist.ru.md).
3. Зафиксировать в отчёте: симптом → находка → фикс.

Слайды презентации: 12–16 в [`Architecture.pptx`](../Architecture.pptx).
